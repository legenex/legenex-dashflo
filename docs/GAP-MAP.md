# DashFlo gap map: list-page congruence and buyer onboarding completion

Produced by W0-AUDIT (`forge-pack/03-plan/WORK-UNITS.yaml`), read-only against the
repository at commit `3c65720` (branch `agent/W0-AUDIT/gap-map`). Every claim below
was verified by reading the cited source directly in this checkout, not by trusting
`docs/STATE.md`'s own self-graded stage summaries. Where a prior "Lead Distribution
rebuild" stage (`docs/STATE.md`, 24-26 August 2026) claimed to fix something in this
surface area, that claim was re-checked against current source and is marked
`closed` only when the fix is actually present, with the proof cited.

Flags: `P0` blocks calling a surface production-ready before the 16 September first
commercial cutover (Contract v3 Section 6), or is an explicit acceptance criterion of
`W8-CONGRUENCE` / `W9-ONBOARDING`. `post-cutover` is real but cosmetic, redundant, or
low-risk polish that can wait. `closed` means a prior stage already fixed it and
current source proves it.

Hours are rough sizing for a focused agent to implement and test the fix, not
including the shared review/deploy overhead already covered by `npm run gate`.

## Summary

- 63 items total: 27 `P0`, 32 `post-cutover`, 4 `closed` (verified fixes from the
  Stage 7 rebuild: unconfigured-RouteMember rendering, the Buyers-tab Deliveries
  count, and the full-page Delivery editor replacement, GAP-46 through GAP-48 plus
  the framing note above them).
- The single highest-value fix for buyer onboarding completion is GAP-57 (vertical
  is never captured, form is not actually per-vertical) combined with GAP-59 (the
  orchestrator currently cannot complete a single real onboarding run without
  Xero/Stripe credentials that Contract v3 explicitly defers past cutover). Between
  them, no buyer onboarded today through the built pipeline would both carry a
  correct vertical and reach `status: 'complete'`, since GAP-59's Xero/Stripe
  blocking prevents completion regardless of the vertical fix.
- The clearest systemic list-page pattern gap is pagination: five different pages
  (GAP-52) hard-cap at 200-500 rows with silent truncation, while a working,
  already-adopted fix (`client/src/lib/fetchAll.js`) exists in the same codebase and
  is used correctly by Reports and Finances.
- Two genuinely separate "buyers list" and "suppliers list" implementations exist
  side by side (Operations vs Campaigns tabs, GAP-38 through GAP-44), which is the
  single largest piece of `W8-CONGRUENCE` scope this audit found.
